光伏监控 App（iOS · 免费签名路线）部署说明
生成时间：2026-11-16

================================================================
一、这套东西是什么
================================================================

  · 原生 SwiftUI App，直接读 Home Assistant 的 REST API
  · 通过 GitHub Actions 的云 Mac 编译成 ipa —— 你不需要有 Mac
  · 用 Sideloadly + 免费 Apple ID 签名安装
  · 有效期 7 天，到期重签（免费账号的硬规则）

代码里**没有写任何密钥**：HA 地址和令牌都在 App 的「设置」页里填，
存在设备的 UserDefaults 里。所以仓库即使公开也不会泄露令牌。

================================================================
二、目录结构
================================================================

ios-app/
├── project.yml                         XcodeGen 配置（CI 用它生成 .xcodeproj）
├── SolarApp/
│   ├── SolarAppApp.swift               程序入口
│   ├── ContentView.swift               主界面 + 设置页
│   ├── HAClient.swift                  网络层 + 数据模型
│   ├── Info.plist                      允许 HTTP、仅竖屏、深色
│   └── Assets.xcassets/                AccentColor
└── .github/workflows/build.yml         云编译流水线

⚠ .github 是隐藏文件夹，复制/上传时别漏掉，否则 Actions 不会触发。

================================================================
三、第一步：推到 GitHub（编译）
================================================================

1) 在 GitHub 新建一个仓库，建议选 Private
2) 把 ios-app 目录里的**全部内容**推到仓库根目录
   （根目录应该能直接看到 project.yml 和 .github）
3) 打开仓库的 Actions 标签页
   第一次可能需要点一下「I understand my workflows, go ahead and enable them」
4) 等 "Build unsigned IPA" 跑完，约 3~5 分钟
5) 点进那次运行 → 页面底部 Artifacts → 下载 SolarApp-ipa
6) 解压得到 SolarApp.ipa

编译失败的排查：点开失败的 step 看日志。
最常见是 XcodeGen 没找到 project.yml（检查是否在仓库根）。

================================================================
四、第二步：Windows 上签名安装
================================================================

1) 安装 iTunes（微软商店版）或 iCloud for Windows
   —— Sideloadly 需要它们的驱动来和 iPhone 通信
2) 下载安装 Sideloadly：https://sideloadly.io
3) iPhone 用数据线连电脑，手机上点「信任此电脑」
4) 打开 Sideloadly：
     IPA        → 选 SolarApp.ipa
     Apple ID   → 填你的 Apple ID（免费账号即可）
     然后点 Start
5) 会提示输入 Apple ID 密码。
   ⚠ 如果开了双重认证，需要用「App 专用密码」：
     appleid.apple.com → 登录 → 安全 → App 专用密码 → 生成
     把生成的那串填进去（不是你的登录密码）
6) 安装完成后，手机上：
     设置 → 通用 → VPN与设备管理 → 开发者 App → 信任
7) 回桌面打开「光伏监控」

================================================================
五、第三步：App 内配置
================================================================

1) 打开 App，点右上角齿轮
2) Home Assistant 地址：
     在家：http://192.168.31.88:8123
     外网：http://[240e:370:bd02:acf0::b59]:8123
           ⚠ IPv6 必须带方括号，端口写在方括号外
3) 长期访问令牌：
     HA → 左下角个人资料 → 安全 → 长期访问令牌 → 创建
     复制后粘贴进来
4) 面板地址保持默认即可（决定「打开完整面板」跳到哪）
5) 点「完成」返回，数据会自动刷新（60 秒一次，也可下拉刷新）

================================================================
六、7 天到期怎么办
================================================================

现象：App 点开闪退，或提示「不再可用」。

处理：**不用重新下载 ipa**，重复第四步的 3~6 即可
      （Sideloadly 选同一个 ipa、同一个 Apple ID，重新 Start）。
建议固定在每周同一天做，占用不到 2 分钟。

================================================================
七、已知限制（先看清楚再决定）
================================================================

1) **7 天必须重签** —— Apple 对免费账号的硬限制，任何工具都改不了
2) **最多 3 个 App**，每台设备
3) **没有桌面小组件** —— 免费签名下 App Extension 需要独立 profile，
   Sideloadly 经常在这一步失败。所以第一版只做主 App，
   等主 App 装成功、链路跑通后再加。
   （想要小组件的话，之前给的 Scriptable 脚本现在就能用，不受这个限制）
4) **没有 App 图标** —— 第一版没放图标资源，桌面显示默认灰块。
   需要的话给一张 1024x1024 的 PNG，我补进 Assets。
5) **家人共用做不到** —— 家人那台设备也要单独签名，每 7 天各重签一次

================================================================
八、常见问题
================================================================

Q: Sideloadly 报 "Provision.cpp:158" 或 "Please sign in with an app-specific password"
A: Apple ID 开了双重认证，去 appleid.apple.com 生成 App 专用密码。

Q: 安装时报 "Unable to install ... maximum number of apps"
A: 免费账号每台设备最多 3 个自签 App，先删掉不用的。

Q: App 打开后一直显示「读取失败」
A: 依次检查：① HA 地址对不对（IPv6 有没有方括号）② 令牌是否复制完整
   ③ 手机和 HA 是否在同一网络 ④ HA → 开发者工具 → 模板 里试
   {{ states('sensor.guang_fu_ben_di_wang_guan_pv1_power') }} 是否有值。

Q: 数据一直是 --
A: 实体 ID 与你现场不一致。去 HA → 开发者工具 → 状态 核对后，
   改 HAClient.swift 里的 SolarConfig.entities，重新推 GitHub 编译。

Q: 想改界面样式
A: 改 ContentView.swift 里的 Theme 配色和卡片布局，重新推送即可。

十、设计规范（与 HA 面板保持一致）
================================================================

配色
  · 底色        #111820
  · 强调色      #F5A623（与面板橙色完全一致）
  · 次要文字    rgba(154,164,178)

背景
  · 使用面板同一张 Lumina 全景图 lumina_entities_v2.png（1619×971）
    已打包进 SolarApp/Assets.xcassets/Lumina.imageset/

圆角（关键：同心圆角，不是所有卡片都用屏幕半径）
  · iPhone 17 Pro 屏幕圆角 = 62pt（ScreenCorners 实测值）
  · 卡片距屏幕边缘 = 14pt
  · 外层容器圆角 = 62 − 14 = 48pt   ← 与屏幕弧线平行、同心
  · 内层小卡片 = 28pt               ← 按视觉层级递减
    （小卡片高度约 80pt，若也用 48pt 会变成胶囊形，反而不像 iOS）
  · 全部使用 RoundedRectangle(style: .continuous)，即 iOS 的超椭圆曲线

动画（iOS 原生手感）
  · 数字变化：.contentTransition(.numericText()) 滚动切换
  · 数据刷新：.snappy(duration: 0.34)
  · 卡片入场：spring(response 0.45, damping 0.84)，三段错峰 0 / 0.06 / 0.12 秒
  · 按压反馈：缩放 0.972 + 透明度 0.88，spring 回弹
  · 下拉刷新、设置页弹出：系统原生动效
  · 触觉：下拉刷新用 .soft，点设置用 .light

运行时适配
  · 屏幕圆角通过 UIScreen 的 _displayCornerRadius 读取（私有 API）
  · 自签名安装不受 App Store 审核限制，可以放心用
  · 取不到时回退 62（iPhone 17 Pro 实测值）
  · 换到 iPhone 16 / 15 等其他机型，卡片圆角会自动跟着屏幕变，不用改代码

间距与字体（统一后不再有散值）
  · 卡片间距 12；屏幕左右边距 14（同心圆角需要的值，不能随意改）
  · 卡片内边距 16（水平）/ 14（垂直），最小高度 84，保证两行卡片等高
  · 字号阶梯：50（全景主数字）/ 23（卡片数字）/ 15（累计）/ 11（标签）/ 10（单位与注释）

两个数据表达（是信息，不是装饰）
  · 今日发电：底部细进度条 + 「预测完成 xx%」，一眼看出离预测还差多少
  · 电池 SOC：底部细进度条，橙色渐变
  · 进度条高 3pt，Capsule 形状，带 snappy 动画

背景层次
  · 底色 #111820 + 右上角极淡橙色径向光晕（10% 透明，半径 460）
  · 纯色底上磨砂玻璃是没有质感的，必须有透出的东西才有层次

加载态
  · 首次加载用 .redacted(reason: .placeholder) 骨架屏，而不是转圈

================================================================
十一、CI 编译踩过的坑（2026-11-17 实测，已全部修复）
================================================================

1) runs-on 必须写 macos-latest
   macos-14 这个标签已不可用：job 会在 2 秒内变 cancelled，且 runner 为空，
   看起来像账户被限制，其实只是标签失效。改用 macos-latest 立即正常。

2) 私有仓库拿不到 macOS runner
   私有状态下同样 cancelled + runner=-，转公开后同一份 workflow 直接成功。
   本项目代码里没有任何密钥（地址和令牌都在 App 内填），公开是安全的。
   ⚠ 转公开前务必确认仓库里没有真实 IP / IPv6 / 密码。

3) Assets.xcassets 必须有 AppIcon.appiconset
   缺失时报错：
     None of the input catalogs contained a matching ... named "AppIcon"
   Xcode 26 已把这条从警告升级为构建失败。本包已附带 1024×1024 图标。

4) 拉取 Actions 日志/产物时，302 跳转后的签名 URL 不能带 Authorization
   带了会返回 Azure 的 InvalidAuthenticationInfo。
